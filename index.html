    Where the threshold is

    Prediction from the same error model the decoder uses, 20,000 shots per point.

    A code only helps when the physical error rate is below a threshold. For this code and circuit it is about 13% per step, far above any real machine (IonQ Forte's two-qubit gates are wrong about 1% of the time), which is why the dial exists.

    Surface codes, which also correct phase errors, have a threshold near 1%. That is the number hardware teams fight for, and the reason Willow's Λ = 2.14 was news.

    The experiment above runs two rounds so that distance 9 fits in 25 qubits. A short memory flatters big codes, so its curves never cross.

    Every machine lands near Λ ≈ 2–3 with the dial at 6%: the dial dominates, and each machine's own noise pulls its Λ down a little. Ions need no swaps, since any two can be entangled directly. On IBM's grids the code is laid along a line of neighbouring qubits, which also needs none, but the ions pay in time: a gate takes about 0.6 ms on an ion and 0.07 µs on a superconducting chip.

    Figure 7

    Coherent errors add up

     

    The dial is a small rotation, not a coin toss. When every rotation turns the same way, their amplitudes add before they are squared, and the matching decoder, which assumes independent random flips, fails more often than the model predicts.

    Pauli twirling fixes it: a Z gate before a rotation reverses it, so each copy of the circuit draws a random sign for every rotation. Averaged over four copies, the errors become exactly the random flips the decoder expects. The same trick, randomized compiling, is used on real hardware.

    Logical error per shot at distance 3 and 5, dial at 6%: every rotation the same way, randomly signed, and the model's prediction.

    How it works

    1. Store one bit in many qubits

      The repetition code copies a logical 0 into d data qubits (000… ) or a logical 1 (111…). Distance d survives up to (d − 1)/2 flips.

    2. Check neighbours, not values

      Each round, an ancilla records whether two neighbouring data qubits agree, without reading either. Qollab's IonQ path can only measure at the end, so every round gets fresh ancillas, read at the end; reading an untouched qubit later gives the same statistics. On IBM's noise models the ancillas are measured and reset every round, as Google does.

    3. Turn the dial

      A rotation on every data qubit before each round, and on every ancilla before it is read, flips it with probability q. Each rotation gets a random sign (Pauli twirling), so coherent errors become the random flips the decoder expects.

    4. One circuit, every size

      IonQ's runners take one job of one circuit. So the lab builds the biggest code that fits, distance 9 in 25 qubits, and reads every smaller code out of it: any d neighbouring data qubits and the checks between them are a complete distance-d memory, with the same noise.

    5. Decode

      From the circuit, the lab lists every single fault and the detection events it would cause (a detector error model). Minimum-weight perfect matching finds the most likely set of faults behind each shot; majority vote looks only at the final data. Each distinct bitstring is decoded once.

    6. Measure Λ

      The failure rate becomes an error per round, ε = (1 − (1 − 2P)1/r)/2, as in Google's 2021 paper; Λ is the ratio between neighbouring distances, fitted across all of them, with 95% intervals from 2,000 bootstrap resamples.

    What this shows, and what it doesn't

    • Only bit flips. A repetition code ignores phase errors, so its Λ is not a surface-code Λ. It shows the mechanism, not a full logical qubit.
    • The dial does the heavy lifting. With native noise alone, distance 5 fails about once in 10,000 shots on these machines. Counting that would take far more shots than a browser run allows.
    • Two rounds. Google fitted up to 50. With r = 2, the error per round still carries some of the start and end of the memory.
    • Simulators are models. IonQ says its noise models should not be used to predict hardware results. Real hardware would add idle dephasing, crosstalk and leakage.
